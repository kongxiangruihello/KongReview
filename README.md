# KongReview

个人用的 macOS 日课应用：把读书、读网页时的摘录，以及记忆卡、札记、问题、笔记集中起来，每天出一份日课——先想，再展开对照，再判分——做完写日评、打卡，成绩记进成绩册。

属于 kong 系列应用。0.6 起由 KongGlean 更名为 KongReview，旧版的数据和设置在首次启动时自动复制过来，旧链接 `kongglean://` 继续可用。

- 应用里的“使用说明”（侧栏）按使用流程介绍各项功能与快捷键。
- 全部版本说明见 [CHANGELOG.md](CHANGELOG.md)；后续打算见 [docs/ROADMAP.md](docs/ROADMAP.md)；每一版的验证记录在 `docs/validation/`。

> 下面“## 版本号 标题”各节是应用“检查更新”面板显示的更新说明（见 `docs/RELEASING.md`），只留最近几版。

## 6.4.0 问题簿、专题笔记本并入札记

作者要求把札记、问题簿、专题笔记本（如“何以为士”）合并为札记，连数据一起合并。

- **侧栏**：“题库”里只留“札记”；问题簿与各本专题笔记本不再单列，加号菜单、“文件”菜单里的“记一个问题”“新建专题笔记本”拿掉。
- **一个问题 → 一条札记**：题目是问题本身；正文依次是状态（待研究、有线索、已解决、搁置，是否常念）、说明、解答、材料说明、原先的归属。挂着的摘录成为札记引用的摘录，挂着的札记写成 `[[链接]]`。
- **一本笔记本 → 一条或几条札记**：没有小标题的，整本一条；有小标题的，每个小标题下的内容一条（题目“笔记本名·小标题”），另有一条以笔记本名为题的“目次”札记，按原来的顺序链接各节。摘录块写成引文并成为札记引用的摘录，札记块写成 `[[链接]]`。
- **日课**：原来的进展题、解答题、复述题都改出论证题。到期日带过来——问题沿用进展题或解答题的，各节沿用其中最早到期的那一段的；搁置的问题一年后再出，目次不出题。札记每天的题数改为原来四项之和（至多 20，“设置 → 日课”里可改），其余三项设置拿掉。
- **回顾与编辑**：“挂到问题”（Q）拿掉；“加入专题笔记本”改为“加入札记”（列最近的 15 条）。
- **数据不丢**：原来的行原样抄进数据库里的 `merged_*` 各表后才从原表删去，`idea_note_origin` 记下每条札记的来历；更新前应用照例先备份学习库。第一次打开时提示一次并入了几个问题、几本笔记本。
- 恢复旧备份、旧版本遗留的专题问题，打开时同样并入。
- **编辑选中的摘录**：摘录列表里选中一条时，工具栏的铅笔按钮编辑这一条（此前这个按钮总是新建，打开的是空白面板）；没有选中时按钮是加号，新建摘录。右键菜单第一项“编辑…”照旧，只选一条时“批量操作”菜单最上面也加了“编辑…”。

## 6.3.6 日课上的译文与按语照回顾的样子显示；文档整理

- **译文与按语**：日课的摘录题展开后，译文、按语用与回顾相同的排版显示（译文 16px 次要色；按语 14px、左侧色条），保留原来的格式。此前日课上不显示译文，出处题展开后不显示按语，要点题、开头题的按语只在题面上以去掉格式的小字出现。展开后题面上那行小字按语收起，不重复显示。
- **文档**：README 只留定位、最近几版、安装与数据；全部版本说明移到 `CHANGELOG.md`。路线图按日课的定位重写，旧路线图原样移到 `docs/ROADMAP-archive.md`。
- **清理**：删去没有任何地方用到的四处代码（`AcademicLayout.swift`、`setBlockPosition`、`sampleCard`、`examRetestCap`）；开发时用的 Python 包（`tree_sitter-….whl`，653 KB）移出仓库。
- 不改数据、设置与排程。

## 6.3.5 补签更显眼

作者要求“特别突出一些补签功能”。此前补签只在成绩册最下方的一小行里，只有翻到那里才看得到。

- **补签卡片**：最近 3 天里有做过日课、只是没写日评的日子时，日课首页、今日日课、成绩册的最上面都出现红框卡片：哪天漏了、**补签后连续打卡会接到几天**（大字，并注明比现在多几天），那天的自评五档（带说明）、一句话，和“补签”按钮。成绩册下方原来那一小行去掉。
- **几天可补时**：每天后面标出补后的连续天数，默认选接得最长的一天（例如昨天、前天都漏了，先补昨天才接得上）。
- **其他提示**：打卡那一行标“可补签 N 天”；打卡图上可补签的日子画红色虚线框，悬停说明补后连续几天；当天的晚间打卡提醒附一句“另有某日可以补签”。
- 断掉的那天还能补签时，不再先问中断原因（补上就不算断）。
- 规则不变：只能补最近 3 天、当天确有日课记录，每月 2 次。依据仍是 Silverman 与 Barasch（2023）：断掉的连续若能修复，人更不容易就此放弃。

## 6.3.4 出处题题面的排版；日课规则的七处修补

- **排版**：作者指出原来摘录的界面看着舒服，日课上改过的难以接受。出处题题面的原文原先用系统文字控件（系统衬线体 18pt、默认行距、转成纯文字），改为与回顾、展开后的原文同一套排版（宋体 22px、行高 1.75、段间留白、保留原格式）。
- 作者要求把日课的逻辑重新捋一遍。通读组卷、作答、课末再练、评分、打卡的代码，找出七处，全部修补：
  1. **打卡**：原先任意一组做完并写了日评就算，只标注完文章、题一道没做也能打卡。改为日课做完——摘录、记忆卡、札记·笔记·问题各组都做完，或至少答了一道后点了“收工”——并写了日评。这几组今天都没有应做时，仍按任意一组做完算。补签、旧记录不变。
  2. **名额**：补考、新录、卡片屡错的摘录排在最前，原先合计可占到每天 10 条里的 9 条。改为三类合计至多占每日条数的一半，其余留给平常的加权抽样。
  3. **新录先录先考**：原先最近录的在前，新录得多时较早的总排不上、30 天后悄悄退回平常的抽样。改为先录的在前；日课页头显示“新录待考 N 条”。
  4. **补考不过期**：原先忘了的摘录只在 2–30 天内补考，积压过了 30 天就不再补。取消 30 天的期限，补考过才不再排；页头显示“待补考 N 条”。
  5. **设了每天的时长**：记忆卡题数满了以后，答了“重来”、还在学习中的卡原先留到明天，现在当天照旧回来。
  6. **弃置的摘录**：当天在别处弃置了的，原先还会出在日课上，现在不再出，也不算待做（与课末再练一致）。
  7. **跨日**：札记、笔记、问题作答前原先不检查是否过了零点（记忆卡、摘录、解答题是检查的），现已补上。

## 6.3.3 加号菜单里加回“添加网页”

- 作者指出：新增里以前有“添加网页”，现在没有了。查明：6.0.1 以前叫“存档网页…”（⌘L），在“文件”菜单与菜单栏图标里，存进“网页存档”并打开网页存档的阅读页；6.0.1 精简时与网页存档一起拿掉，6.1.0 清理时删去了打开面板的函数（`showAddArticle`），面板本身还在。
- 网页存档的阅读页已删，原样恢复会存到看不见的地方，所以改为：整篇正文存为一条摘录，出处是这个网页（标题、作者、网址；按网址认出处，不按标题并入同名的书）；同一网址已有整篇的不重复；存后打开这个出处。正文满 1000 字的进入“今日标注”的待标文章。
- 入口：加号菜单“添加网页…（⌘L）”与“文件 → 添加网页…”（⌘L）；面板仍自动填入浏览器当前页面或剪贴板里的网址。
- 设置里已失效的 `kongreview://save?url=…（整页存档）` 说明删去（6.0.1 起没有对应的处理）。

## 6.3.2 日课上的记忆卡、摘录用原来的编辑窗口

- 作者指出：记忆卡、摘录原本就有编辑窗口（记忆卡学习页右上角的“编辑这张卡”、摘录列表里的编辑），6.2.1 在日课上另做的“编辑这道题”面板不如原来的好用。
- 现在日课上的记忆卡题标题行右边是“编辑这张卡”（⌘E），打开与学习页相同的记忆卡编辑窗口（`store.editCard`）；摘录题是“编辑这条摘录”（⌘E），打开与摘录列表相同的摘录编辑窗口（`store.edit`）。保存后按 id 重取，日课上换成改过的内容；同一道题不重置，展开与否、“我的回答”不动。
- 札记、笔记、问题没有可在日课上弹出的原编辑窗口（打开它们要离开日课），仍用 6.2 的“编辑这道题”面板。

## 6.3.1 更新时进度不再停在八成；编好的程序不再重编

- **进度按用时走**：编译新版本（`swift build -c release`）里编译 KongReview 本身是一整步整模块优化，作者的 Mac 上约 56–69 秒，其间几乎没有输出，原先进度条会在约 81% 停一分钟。现在编译段按已用时间推进，说明里写“已用 34 秒（上次用了约 68 秒）”；超过上次用时停在该段的 97%，说明改为“比上次久一些，请稍候”。每次编译完记下用时（`update.lastCompileSeconds`），没有记录时按 70 秒估计。
- **跳过测试时重新分配进度**：测过而跳过测试的更新，几乎整段都是编译；原先编译一开始就显示 53%，现在从约 13% 起。
- **编好的程序不再重编**：同一份源码（git 树）、同一版 Swift、同样的依赖版本（`Package.resolved`）在本机编译过，`Tools/build-app.sh` 直接用编好的程序，只重新写 Info.plist 和签名。编好的程序存在 `~/Library/Caches/KongReview-updates/builds/`，只留最近 3 份。合并前在本机测试、打安装包时已编过同一份源码，合并后“立即更新”就不必再编。
- **依赖版本写进仓库**：根目录的 `Package.resolved` 原先不提交，每个源码文件夹各自解析 GRDB 的版本——作者 Mac 上测试用的是 GRDB 7.11.1，应用内更新编出的正式应用用的是 7.12.0，测的和装的不是同一版依赖，“编好的程序”也因此永远对不上。现在把正式应用所用的 `Package.resolved`（GRDB 7.12.0）提交进仓库，测试、打安装包与应用内更新用同一版；升级依赖要改这个文件并重新测试。
- `Tools/build-app.sh` 在源码有本地改动、因而不用“测过 / 编过”的记录时，把改动列进日志，便于查原因。

## 6.3.0 日课；自评偏高的题；加号菜单；更新更快

- **考试改为日课**：界面上的说法全面改过——考场 → 日课，考场门口 → 日课首页，今日试卷 → 今日日课，卷面 / 卷子 → 日课，答卷 → 做日课，交卷 → 收工，卷尾再考 → 课末再练，补考 → 补练，成绩单 → 今日小结，每天考多久 → 每天做多久；成绩册、题、判分照旧。只改文字，数据、设置与排程不变。
- **自评偏高的题**：成绩册“常错的题”下面一节，列出近 30 天最近一次判“记得”、写下的回答里要点却不到一半的题（摘录、记忆卡、札记、笔记、解答题），点题面打开，“今天再练”放进今天的课末。
- **加号菜单**：侧栏顶上的“＋”与“题库”旁的“＋”是同一个菜单，列出所有能新建的（摘录、快速录入浮窗、记忆卡、批量粘贴问答、札记、随手札记浮窗、问题、专题笔记本、出处）与导入（KongFolio、LiquidText、Anki）。
- **更新更快**：同一份源码（git 树相同、Swift 版本相同）在本机测过、全部通过的，“点一下就更新”不再测一遍（约省 25 秒）。测过的记录在 `~/Library/Caches/KongReview-updates/tested-trees.txt`，测试脚本与更新各自写入。
- `Tools/build-dmg.sh` 可用 `KONGREVIEW_DMG_DIR` 把安装包放到别处（测试时放缓存目录，不同步 iCloud）。

## 安装与更新

- **第一次安装**：双击仓库根目录的 `安装KongReview.command`。它把源码放到 `~/Developer/KongReview`，跑完测试后编译、备份学习库并安装。只需要 Apple 命令行工具（`xcode-select --install`）。
- **以后更新**：应用里菜单“KongReview → 检查更新…”，点“立即更新”。应用取 GitHub 上 main 分支的最新代码，在本机测试、编译、签名后换上新版。细节见 [docs/RELEASING.md](docs/RELEASING.md)。
- **安装包**：`./Tools/build-dmg.sh` 生成 DMG，用于拷到别的 Mac。本机签名，没有公证；第一次打开若提示“无法验证开发者”，在访达中右键点 KongReview →“打开”。

## 网页摘录

**书签小程序**：打开“设置 → 摘录 → 复制书签代码”，在浏览器里新建一个书签，把代码粘贴到网址栏。阅读网页时选中文字，点这个书签，KongReview 就会弹出新建面板，标题和网址已经填好，补上标签后保存。

> 如果在 Safari 中点书签没有反应：先在 Safari 设置 → 高级 中勾选“显示网页开发者功能”，再到“开发”菜单启用“允许来自智能搜索栏的 JavaScript”。第一次跳转时浏览器会询问是否允许打开 KongReview，选允许即可。

**链接格式**，可供快捷指令、kongfetch、Alfred 等工具调用：

```
kongreview://add?text=学而时习之&title=论语&author=&url=&location=学而第一&tags=论语,学
```

参数需要做 URL 编码。`text` 为必填项。

## 数据

全部数据保存在一个 SQLite 文件中：

```
~/Library/Application Support/KongReview/kongreview.sqlite
```

在“设置 → 数据”里可以直接在访达中打开这个位置。备份时复制整个文件夹即可。
