# 6.4.2 更新不再从头测、从头编

2026-11-12。作者发来更新面板的截图（6.4.0 → 6.4.1，已用 1:43，停在“编译新版本：已用 63 秒（上次用了约 77 秒）”），说“版本更新时间太久”。

## 原因

截图里“编译并运行全部测试”“编译新版本”两步都真的做了，没有跳过。6.3.0、6.3.1 做的“同一份源码在本机测过、编过就跳过”是按整棵 git 树认的（`git rev-parse HEAD^{tree}`）。6.3.6、6.4.0、6.4.1 三版，都是在作者的 Mac 上测完（并打了安装包）之后，又往分支里提交了一份验证记录：

| 版本 | 在 Mac 上测的提交 | 分支末端（合并进 main 的） |
|---|---|---|
| 6.3.6 | 508dd66 | cd1988c（多两次验证记录） |
| 6.4.0 | f648688 | 1a03cb6（多一次验证记录） |
| 6.4.1 | 1374914 | 多一次验证记录 |

多出的只是 `docs/validation/` 下一个文件，但整棵树的指纹变了，合并后的更新在“测过”“编过”两份记录里都找不到，于是从头测（约 40 秒）、从头编（约 63—77 秒）。这是这几版的做法造成的，不是作者机器的问题。

## 改法

`Tools/build-app.sh` 的指纹改为只算会进程序和测试的部分：

```
git ls-tree HEAD -- KongReview KongReviewTests Packages Package.swift Package.resolved Tools Web | shasum
```

README、CHANGELOG、`docs/`、`project.yml`（版本号写进 Info.plist，每次组装时重写，不在编好的程序里）改了不算换了源码。作者 Mac 上的“测试KongReview.command”改成同一个算法（原脚本备份为“KongReview测试日志/测试KongReview.command.bak-1112”）。`docs/RELEASING.md` 加一节写明：测完之后只能再改说明文档。

没有在本机测过的源码仍然完整测试、编译，这一点不变。
