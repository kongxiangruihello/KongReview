## 起因

6.0 把 KongReview 定位为“考场”，拿掉了与考察无关的功能。6.0.5 删了这些功能的页面入口，但页面代码和数据层函数还留着。ROADMAP 记了两条待办：

- v6.0.5：“学习计划、学习旅程、研究项目、网页存档残留的数据层代码另行清理（数据保留）”
- v6.0.8：“6.1：清理……；深色模式逐页检查”

## 怎样找出残留代码

1. **类型**：反复找“名字在应用代码里只出现一次”（即只有定义）的 struct、enum、class，删去后再找，直到没有新的为止。
2. **函数**：同法找只出现一次的 `func`，并列出每个函数在测试里被引用的次数。只被测试引用的，看它属于哪个已拿掉的功能，再决定删不删。
3. **测试**：引用了已删符号的测试函数删去；整个文件都删空的，文件也删去。几处测试只是顺带用到已删函数，就改写，不删：
   - `V601`：书籍小结改用 SQL 查表。
   - `V605`：删去打开复盘的两行。
   - `V411`：期间复盘统计改用 COUNT 查询。
4. **保留**：仍在用的通用接口照旧保留，例如 ingest、articlePage、duplicateCard 和 `SlimSwitch`。`SlimSwitch` 仍被 `RevisitLimits.saved()` 与 `SlimUpgrade` 引用。

## 实现范围

- **删去**：残留的页面与数据层函数，涉及以下已拿掉的功能：
  - 学习计划（草稿、今日计划、周计划、计划复盘）
  - 学习旅程、学习循环
  - 个人成长（分项、走势、历史）、复盘步骤与札记复盘
  - 研究项目（概览、阶段、写作记录）、写作统计

- **整删的文件**：`HomeV5Database.swift`、`GrowthBreakdownDatabase.swift`、`LearningPlanViews.swift`。
- **代码量**：应用代码 43 个文件 +97 / −2893 行；测试 21 个文件 +8 / −1282 行。
- **数据**：表结构与已有数据一律保留，不加迁移，完整备份照旧带上这些表。
- **修正**（窗口检查中发现）：
  - **今日试卷页头**：在 823 点宽的窗口里，原来会把“记忆卡 4/23”“卷尾再考 1 道”“先交卷，看成绩单”挤成两行。现在各项不截字，放不下时卷尾再考与“先交卷”另起一行（`ViewThatFits`）。
  - **记忆卡首页按钮**：原来截成“学…”“每…”“新…”。现在放不下时，“学习全部牌组 / 每日学习量 / 新建卡片”另起一行。
  - **编辑录入预设**：编辑已有预设时，标题误显示“新建录入预设”，保存时也跳过了“预设已被改动”的检查。原因是 `sheet(item:)` 读的是另一个 `@State`（`original`），读到的是上一次的旧值。现在把预设和它原来的样子合成一个 `CardEntryPresetEditTarget` 交给 sheet。保存本来就按 id 覆盖，所以以前不会多出一份或丢数据。
- **菜单**：新增“考场 → 普通卡片样式…”。工具栏里的“卡片模板”下拉菜单照旧可用。
- **预览应用**：启动参数 `-previewAppearance dark` 会以深色模式打开，只对预览版（`PreviewLibrary.isEnabled`）生效。本次检查完已把测试脚本恢复为浅色。
