# 6.0.2 点一下就更新（仿 KongSeek）

2026-11-03。在作者的 Mac 上验证：分支 `claude/v6.0.2-source-update`（7578e3c）全新下载、编译并运行全部测试；首次安装；在正式安装的应用里实际点按更新流程。

## 实现范围

- `AppUpdater` 改为从源码更新（写法沿用 KongSeek 的 `Updater`）：源码文件夹 `~/Developer/KongReview`（不存在时从 GitHub 克隆；已有别的文件则不动并说明）→ `git fetch origin main`（有代理经代理，45 秒超时）→ 源码换到 `origin/main`（本地改过、与近 200 个已发布版本都不同的文件让更新停下）→ `Tools/build-app.sh --test` → 核对新版本（标识、版本号、签名有效；当前用证书签名时须满足同一指定要求）→ 备份学习库（`BackupService.backupNow`）→ 助手脚本等应用退出、把当前版本移到“应用备份”、换上新版、去扩展属性、重新打开（复制失败则换回）。
- 检查：GitHub 上 `project.yml` 的版本号比本机新，或有本机提交之后的新提交（`--no-merges`）。README 里比本机新的各节作说明；更新后第一次打开显示改动。
- 进度：`BuildLogProgress`（核心包）读构建输出——编译测试（n / m）、测试已通过 x / y 项（核心包与应用累计）、编译新版本（n / m）、打包、签名；面板六步 ✓ ● ○ ✕、百分比、用时；首页一行进度；失败时说明哪项测试、哪一行编译错误或网络问题，可看构建日志、重试。
- 自动检查：启动 30 秒后与每 6 小时（可关），有更新只在首页提示。设置“更新”页：版本、签名、上次检查、代理（手填或系统代理）、源码文件夹、用本地源码重新构建、回退到上一版、更新日志。
- 编译时 SwiftPM 取依赖（GRDB）与 git 走同一个代理。
- 安装前退出：先收起窗口上的面板（挂着面板时 macOS 不让退出），仍被拦下就 5 秒后直接结束进程；助手脚本最多等 60 秒，应用没退出就放弃安装、不动当前版本。
- `Tools/build-app.sh`：`--test`（先编译应用测试，再测核心包、应用）、`--install`（退出应用、用 SQLite 在线备份学习库、旧版本移到“应用备份”、安装、打开）；记下提交号 `KRSourceCommit`；钥匙串里有 KongReview / KongSeek / KongFetch 的本地签名证书就用它。`Tools/build-dmg.sh` 改为调用它。仓库根目录 `安装KongReview.command` 用于第一次安装。
- 原来读 GitHub Releases 下载 DMG 的代码不再使用（核心包里的版本比较与安装助手脚本复用）。

## 实地验证（作者的 Mac）

1. 首次安装：`安装KongReview.command`（分支版）把源码克隆到 `~/Developer/KongReview`，跑完全部测试、编译、签名，备份学习库到 `安装前备份/`，把原来的 6.0.0 移到 `应用备份/`，装上 6.0.2 并打开。第一次打开时 6.0.1 的精简留存照常导出并提示。
   - 发现：第一次没有给编译传代理，SwiftPM 取 GRDB 直连 GitHub 超时卡住；已改为编译也走代理，重试后通过。
2. 检查更新：菜单“检查更新…”显示“已是最新”（GitHub main 为 6.0.1）。
3. 设置 → 更新 → 用本地源码重新构建：进度面板依次打勾（测试：已通过 613 / 790 项……），1 分钟左右完成。
   - 发现：面板挂在窗口上时应用退不出，助手脚本等 60 秒后放弃（当前版本未动）；已改为先收起面板再退出、仍不退就直接结束。
4. 改后重装，再点“用本地源码重新构建”：完成后应用自动退出、换上新版并重新打开（更新日志：“安装完成，重新打开”）。
