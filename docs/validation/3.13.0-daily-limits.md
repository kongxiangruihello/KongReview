# 3.13.0 每日学习量：全库合计、仅今天加量与混合学习

2026-10-20。本版代码在 Linux 环境编写，该环境没有 Swift 工具链，**尚未编译，也未运行任何测试**。仅用 tree-sitter 对改动的 Swift 文件做了语法解析（0 个解析错误）；类型检查、单元测试、窗口操作和安装包都需要在 Mac 上完成，下列“待验证”各项在完成前不计为通过。

## 实现范围

1. **统一账本**（`KongReviewCore/DailyLimits.swift`）：`DailyLimitSettings`（牌组默认值、全库合计、今日加量）与 `DailyLimitLedger`（牌组上限含今日加量、全库合计含今日加量、按牌组的今日已学）。某牌组此刻可学＝min(牌组余额, 全库余额)。已彻底删除、无法归入牌组的卡只计入全库合计。
2. **两条统计路径同口径**：数据库直接查询（`cardLearningSummary`、`deckSummaries`、`homeLearningSummary`）与后台快照（`derivedLibrarySnapshot`）都改用账本；`CardStudyAvailability.summarize` 先按牌组计数，再与全库合计余额取小，并说明是牌组上限还是全库合计挡住、合计为 0 时不显示“明天可学”。首页、菜单栏、提醒的今日待学改用全库队列，不再直接相加各牌组数字。
3. **学习会话**：单个牌组、全部牌组（新增 `startStudyAllDecks`）取卡都受牌组余额与全库余额约束；笔记本学习保留原设计（以牌组默认值为本笔记本额度），同时受全库合计约束。
4. **仅今天加量**：`extraPlan` 只在真正挡住的一级加量（牌组或全库合计；“全部牌组”范围按牌组名顺序补足），以当天日期记录在 `cards.todayExtra`，换日自动失效；牌组改名时转移；不进入完整备份。
5. **设置与备份**：全库合计存为 `cards.totalNewEnabled`／`cards.totalNewPerDay`、`cards.totalReviewsEnabled`／`cards.totalReviewsPerDay`，加入完整备份白名单；所有上限输入统一为 0–9999。
6. **界面**：每日学习量面板（`DailyLimitsView`）、牌组卡片上限标签（`DeckLimitChip`）、首页与完成页“今天再学”（`TodayExtraButtons`）、首页“学习全部牌组”与全库合计说明、设置页数字框与合计开关、牌组选项数字框、统计页按牌组表的上限含今日加量并在合计行显示全库上限。
